## Purpose

This generated GitHub Agentic Workflows maintenance workflow closes expired discussions, issues, and pull requests on its daily schedule. Manual and reusable calls can select additional repository-maintenance operations. The source comments say generation is enabled by expiring safe outputs, steering, ledgers/work queues, or maintenance settings in `aw.json`; the workflow is generated by gh-aw and must not be hand-edited.

## When it runs

The scheduled run and calls with an empty or `none` operation run the three expired-resource cleanup jobs, except on forks. A selected operation runs only for `workflow_dispatch` or `workflow_call` and only on a non-fork repository. A concurrency group based on workflow and repository serializes writes.

## Execution flow

| Job | Runs when | What it does |
| --- | --- | --- |
| `close-expired-discussions` | Scheduled/default operation, non-fork | Closes expired discussions with `discussions: write`. |
| `close-expired-issues` | Scheduled/default operation, non-fork | Closes expired issues with `issues: write`. |
| `close-expired-pull-requests` | Scheduled/default operation, non-fork | Closes expired pull requests with `pull-requests: write`. |
| `run_operation` | Manual/call with an eligible operation | Checks maintainer access, installs gh-aw, then handles `disable`, `enable`, `update`, or `upgrade`. |
| `update_pull_request_branches` | Operation is `update_pull_request_branches` | Checks maintainer access and updates PR branches. |
| `apply_safe_outputs` | Operation is `safe_outputs` | Replays safe outputs for the supplied run URL/ID. |
| `create_labels` | Operation is `create_labels` | Creates missing labels after the permission check. |
| `activity_report` | Operation is `activity_report` | Reads up to 500 workflow log records from the previous week, caches report logs, and creates a report issue when report content exists. |
| `forecast_report` | Operation is `forecast` | Runs gh-aw forecast with a 30-minute limit and creates a forecast issue. |
| `close_agentic_workflows_issues` | Operation is `close_agentic_workflows_issues` | Closes no-reproduction agentic-workflows issues after the permission check. |
| `validate_workflows` | Operation is `validate` | Validates workflows and files an issue for findings. |

Jobs request their own permissions; workflow-level permissions are empty. Write-capable maintenance operations perform an admin/maintainer check.

## Inputs, outputs, and access

`workflow_dispatch` offers an `operation` choice and `run_url`; `workflow_call` accepts those as strings. The operation choices are `none`, `disable`, `enable`, `update`, `upgrade`, `safe_outputs`, `create_labels`, `activity_report`, `close_agentic_workflows_issues`, `update_pull_request_branches`, `validate`, and `forecast`. `run_url` is required by the safe-output replay operation, though the input itself is optional.

The reusable workflow exposes `operation_completed` and `applied_run_url`. Jobs use the GitHub token with operation-specific permissions; no additional secret input is declared.
